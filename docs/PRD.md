# RoboDataOps 首版产品规格

状态：软件首版已实现；用户需求验证和下游效果仍待开展。原始长方案保留为规划记录，当前范围以本文和 README 为准。

首要用户是按批次验收机器人示教数据、安排下一周期补采的数据 PM。协作者是质检人员、训练工程师和采集负责人。痛点假设为跨表关联、缺少异常证据、统计口径不清和预算变化后的重复计算，尚未作为已验证市场事实。

## 用户工作流

固定来源 → 完整 episode 读取 → 规则与证据 → 人工复核 → 唯一验收状态 → task 覆盖 → 预算规划 → 草稿导出 → 按原契约到货核对。

每条轨迹的状态优先级：仍生效的硬阻断或人工确认 → 必需检查未完成 → 影响验收的未决发现 → 按当前口径计入。驳回一个发现不会撤销同一轨迹的其他阻断。表格检查不推断任务成功或训练价值。

## 首版验收

- 只支持已核对的 LeRobot v3 Parquet 布局；严格检查必需字段声明、索引和元数据类型。
- 共用同一核心处理层，CLI 与页面不各自计算业务指标。
- 一条轨迹即使多条告警，覆盖统计仍只计一次。
- 低运动、短轨迹和过大间隔仅要求复核，不自动删除源数据。
- 所有分配遵守相同预算与产能约束；求解超时、有可行解、不可行和最优分开显示。
- 计划冻结数据、规则、复核和目标版本，旧计划不会被新设置改写。
- 回流仅支持同源同任务同契约，拒绝平台、FPS 或必需 schema 变化；同进程串行去重。
- 回流核对与累计数据导入分开：更新全量覆盖时需导入累计快照。
- 默认演示有合成和公开两种来源，业务报价与产能是模拟输入。

不属于当前首版：完整视频解码和物理同步验证、语义成功评分、模型价值预测、多供应商排期、自动原始文件合并、多进程并发写入和公网多租户。

可观察指标：决策任务用时、关键错误、证据追溯、复核负担、约束违反和真实交付记录。软件自动化结果见验证报告；用户与策略指标尚无实测值。
